# افزونه بازبینی داخلی سامانه مؤدیان انبارین

این افزونه یک محل امن سمت سرور برای نگهداری **پیش‌نویس داخلی** تولیدشده در انبارین فراهم می‌کند. این افزونه به سامانه مؤدیان متصل نمی‌شود، صورتحساب رسمی تولید نمی‌کند و هیچ اطلاعاتی را برای سازمان امور مالیاتی ارسال نمی‌کند.

## نصب

1. پوشه `anbarin-taxpayer-review` را در `wp-content/plugins/` قرار دهید.
2. از پیشخوان WordPress افزونه «Anbarin Taxpayer Internal Review» را فعال کنید.
3. سایت را فقط با HTTPS در دسترس قرار دهید.
4. درخواست‌ها باید با احراز هویت استاندارد REST وردپرس ارسال شوند: نشست مدیر همراه REST nonce در محیط مرورگر وردپرس، یا Application Password اختصاصی مدیر از یک سرویس سمت سرور. **Application Password را داخل برنامه موبایل/وب عمومی قرار ندهید.**

## API

- `POST /wp-json/anbarin/v1/taxpayer/reviews` ذخیره پیش‌نویس داخلی
- `GET /wp-json/anbarin/v1/taxpayer/reviews?limit=30` فهرست متادیتای پیش‌نویس‌ها (حداکثر ۱۰۰)
- `DELETE /wp-json/anbarin/v1/taxpayer/reviews?id=123` حذف یک پیش‌نویس مشخص (فقط مدیر مجاز)

دسترسی فقط برای کاربری با مجوز `manage_options` مجاز است. وردپرس احراز هویت REST را انجام می‌دهد. حداکثر حجم هر سند ۵۱۲ کیلوبایت و حداکثر تعداد ردیف‌های هر پیش‌نویس ۵۰۰ است. پاسخ‌های این مسیرها با هدر `no-store` از کش مرورگر و واسط‌ها منع می‌شوند. ساختار ورودی باید `documentKind=anbarin-taxpayer-internal-review`، نسخه ۱ و `isOfficialOrganizationPayload=false` داشته باشد. کلید یکتای مبتنی بر شناسه فاکتور و زمان snapshot از ثبت تکراری یک سند جلوگیری می‌کند.

## وضعیت و محدودیت‌ها

- وضعیت ذخیره‌شده همیشه `internal_review` است؛ وضعیت «ارسال‌شده» یا «تأییدشده» وجود ندارد.
- JSON پیش‌نویس در جدول اختصاصی WordPress ذخیره می‌شود. دسترسی به API محدود است؛ مدیر سایت باید از پایگاه داده و نسخه‌های پشتیبان نیز مانند اطلاعات مالی/شخصی محافظت کند.
- این مرحله هیچ اتصال شبکه‌ای به سازمان، امضا، رمزنگاری مخصوص صورتحساب، شناسه یکتای مالیاتی، یا ارسال مستقیم/معتمد پیاده‌سازی نمی‌کند.
- پیش از هرگونه ارسال واقعی باید آخرین دستورالعمل و schema رسمی سازمان، روش امضا/رمزنگاری، احراز هویت و پاسخ‌های پذیرش/رد بررسی و جداگانه پیاده‌سازی شوند.
- برنامه فعلی هنوز به این افزونه متصل نشده است؛ این جزء فقط زیرساخت اختیاری سمت سرور را آماده می‌کند. برای اتصال از اپ باید ابتدا روش احراز هویت مناسب زیرساخت میزبانی و کاربران برنامه طراحی شود؛ اعتبار مدیر WordPress نباید در کلاینت جاسازی شود.

## حفاظت و نگهداری داده

- حذف فقط به‌صورت صریح و برای شناسه مشخص از طریق درخواست `DELETE` انجام می‌شود؛ پاک‌سازی زمان‌بندی‌شده یا حذف خودکار فعال نیست.
- خروجی فهرست صرفاً متادیتا است و محتوای کامل سند را برنمی‌گرداند.
- مدیر باید سیاست نگهداری، دسترسی پایگاه داده، پشتیبان‌گیری و حذف امن نسخه‌های پشتیبان را در زیرساخت خود تعیین کند.
